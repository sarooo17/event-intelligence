# MCP Event Intelligence v0.12.0-next.0 — integration prerelease candidate

**Status:** proposed pre-1.0 integration candidate. This file does not
authorize publication. The npm version is not assumed to exist until the
manual release workflow succeeds and the actual npm registry confirms it.

## Purpose

Let a real host runtime (including but not limited to the Muffin fork)
install and evaluate the **single canonical**
`mcp-event-intelligence/embedded` `createEventIntelligence()` facade using
public npm package types and a repeatable lockfile, rather than a CI-only
source tarball.

## Candidate highlights (source as of candidate PR)

- Canonical runtime-neutral embedded facade, HostContract v1 and host-owned
  MCP connection, target, authorization and lifecycle callbacks.
- Portable event-watch tools, owner-scoped control and custom host tool names.
- Runtime continuation targets are opaque host keys; no imposed chat, Turn,
  task, graph, principal/policy or model SDK.
- Explicit opt-in delivery receipt acknowledgment when the host requires
  `wake.receipts`; the host must still atomically persist work and receipt.
- PostgreSQL16 shared EI state, wake/replay recovery and host-boundary
  atomic-queue reference tests; no automatic claim of production SLO.
- Archive witness provenance, indexed trigger-match lookup and conformance
  fixtures currently integrated on main.
- Released npm v0.11.0 remains unchanged. v0.12.0-next.0 is a separate
  semver prerelease and must never be tagged as the stable `latest` until
  deliberately promoted.

## Proposed publication gates — do not bypass

1. Exact SHA review by Codex with zero unresolved findings and all applicable
   CI, packed Clean-room Smoke and PostgreSQL tests green.
2. `node scripts/check-release-manifest.mjs` and `npm run pack:check`
   validate manifest, lockfile, MCP Registry metadata and public exports.
3. Confirm the desired prerelease tag is available, and release from an
   operator-approved **main** commit using manual GitHub Actions `Publish npm`
   with `confirm=publish`. Do not publish the PR branch.
4. Because npm CLI normally publishes the package under the default
   `latest` dist-tag when no tag is specified, the publish workflow
   MUST support and enforce `--tag next` for prerelease versions **before**
   operator publication. Keep this PR unmerged or unpublished until that
   separate policy is reviewed.
5. Only after verifying the actual npm version and `next` dist-tag, create
   a consumer-owned PR updating the Muffin `package.json` and lockfile and
   run its normal CI with source/head review. Do not merge draft fork #17 on
   a mismatched 0.11.0 pin.
6. Do not claim independent external-host certification, distributed host
   receipt atomicity, Railway SLO compliance or v1 production readiness.

This prerelease is an integration **test vehicle**, not a v1.0 release.
