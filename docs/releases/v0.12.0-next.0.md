## Purpose

Let a real host runtime (including but not limited to the Muffin fork)
install and evaluate the **single canonical**
`mcp-event-intelligence/embedded` `createEventIntelligence()` facade using
public npm package types and a repeatable lockfile, rather than a CI-only
source tarball.

## Candidate highlights (shipped integration surface)

- Canonical runtime-neutral embedded facade, HostContract v1 and host-owned
  MCP connection, target, authorization and lifecycle callbacks.
- Portable event-watch tools, owner-scoped control and custom host tool names.
- Runtime continuation targets are opaque host keys; no imposed chat, Turn,
  task, graph, principal/policy or model SDK.
- Explicit opt-in delivery receipt acknowledgment when the host requires
  `wake.receipts`; the host must still atomically persist work and receipt.
- PostgreSQL16 shared EI state, wake/replay recovery and host-boundary
  atomic-queue reference tests; no automatic claim of production SLO.
- Archive witness provenance, indexed trigger-match lookup and conformance
  fixtures currently integrated on main.
- The npm 0.11.0 artifact remains immutable and an independently exact-pinned consumer retains its version until its owner updates the dependency and lockfile. The 0.12 prerelease is tagged `next`, not `latest`.

## Breaking API changes and migration disposition

1. **Model-facing host control:** update code using the removed boolean `authorize()` option to a host-owned `control(request)` decision; host handles policy, approval/interrupt and authoritative execution. Do not replace a denial with an implicit allow.
2. **Conformance v3:** supply durable `wakeId`, `runtimeReceiptId` and `readWakeReceipt(wakeId)` in the host adapter; a successful in-memory delivery array does not establish restart-safe receipt semantics.
3. **Canonical embedded facade:** consumers electing to upgrade should compile against this exact prerelease's current `createEventIntelligence()` signatures and conformance kit. No historical host-vendor facade or adapter is supplied automatically.
4. **Persisted-state compatibility:** *do not attempt an in-place mixed-version worker rollout*. Stop/fence existing workers and record the installed version, Pattern signature contract, schema marker, provider cursor state and host receipt boundaries. Take a verified off-host backup and rehearse restoration in an isolated environment. If the new candidate refuses startup, use the explicitly tested snapshot/reset/operator-replay path in [POSTGRES-SIGNATURE-OPERATOR-DRILL](../POSTGRES-SIGNATURE-OPERATOR-DRILL.md) only after acknowledging its destructive nature and reconciling outstanding host receipts. The CI drill is not an automated production upgrade.
5. **Rollback:** pin the prior package and restore compatible pre-upgrade state under a coordinated host-owned procedure; do not treat downgrading npm alone as a safe database rollback.

## Public release signoff still blocked

The prerelease does **not** establish (a) an independently authored production host, (b) multi-region/primary failover and remote provider + external host production SLO, (c) immutable WORM source/audit retention with safe pruning, (d) a full independent security review, or (e) final stable 1.0.0 package and operator upgrade evidence. These are explicit blocked rows in [v1-readiness.json](./v1-readiness.json), especially #45/#47/#50. The #42 product-owner waiver of independent host authorship does not waive security or reliability requirements.

**Do not re-publish this immutable prerelease version, change `latest`, ship an automatic downstream pin update, or mark #50 closed merely because this documentation exists.**
