# MCP Event Intelligence v0.5.0

v0.5.0 turns Event Intelligence into an advanced MCP-native complex event processing layer for durable agent workflows while preserving the existing embedded, host-owned integration model.

## Pattern AST v2

The release adds an additive recursive Pattern AST v2 with:

- nested `event`, `allOf`, `anyOf` and `sequence` nodes;
- sequence contiguity through `next`, `followedBy` and `followedByAny`;
- repeat/optional quantifiers with greedy/lazy preference and explicit internal contiguity;
- bounded negative patterns and durable absence/debounce semantics;
- within, sliding, tumbling, hopping, session and count windows;
- cross-event comparisons and arithmetic expressions;
- aggregates including sum, avg, min, max, count, countDistinct, first, last, nth, stddev and percentile;
- state-transition operators including changed, changedFrom, delta, percentChange, stableFor and threshold crossings;
- typed partitioning, overlap controls and after-match skip semantics;
- bounded candidate, semantic-evaluation and raw-buffer budgets.

## Semantic CEP

`semantic` is now a first-class vendor-neutral Pattern AST node.

The node executes through the existing `SemanticEvaluator` abstraction. TypeSafe Jev remains the bundled optional evaluator when configured, rather than being hard-coded into the trigger language.

Semantic execution is explicit, auditable and bounded by timeout and evaluation budgets.

## Event-time correctness

v0.5.0 separates provider `occurredAt` from host `receivedAt`, adds bounded `allowedLatenessMs` watermark semantics, preserves alternate event-time candidate windows, and hardens negative/debounce finalization against late delivery.

Derived events propagate semantic event-time separately from materialization time.

## Agent authoring

The public trigger language is now self-describing through:

- embedded `describeTriggerLanguage()`;
- MCP `trigger_language_describe`;
- the shared `TriggerPlanInputSchema`.

The planner exposes the full temporal language and Pattern AST v2 without requiring agents to construct the internal trigger representation from memory.

## Derived events

Pattern v2 measures can be projected into derived-event payloads with schema inference and source-path validation.

## Runtime safety

The release adds:

- typed/canonical partition keys;
- bounded per-partition raw event buffers;
- lifecycle capacity enforcement when one ingest yields multiple matches;
- guaranteed-binding validation for advanced nodes and measures;
- fail-closed unresolved comparisons;
- explicit semantic-evaluator unavailability policy;
- replay-safe and lateness-aware matching regressions.

## Compatibility

This is an additive pre-1.0 minor release.

- Existing legacy trigger definitions remain executable.
- The internal persisted Event Intelligence protocol/schema identifiers remain on the v0.1 compatibility line.
- `compileLegacyTriggerToPatternV2()` is available for migration and differential verification.
- The primary architecture remains embedded/host-owned; EI does not take ownership of provider MCP credentials or duplicate host connections.
- MCP Events support remains experimental and isolated behind a versioned compatibility profile.

## Known limits / next evidence

The bundled JSONL store remains reference-grade single-process persistence. The next maturity work should focus on scale/chaos benchmarks, distributed storage/partition ownership, broader conformance/property testing and production evidence.

The Pattern v2 semantic cache is currently evaluation-pass scoped; durable cross-event/restart semantic caching is intentionally deferred.
