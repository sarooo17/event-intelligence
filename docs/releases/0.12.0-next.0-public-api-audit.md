## Real pre-v1 legacy behavior removed from CURRENT SOURCE

- Canonical `createEventIntelligence()` requires an **actual explicit
  runtimeReceiptId**, even without an optional `HostContract` handshake.
  Undefined delivery **cannot finalize a wake** with a synthesized wake-ID
  receipt. Stable `EVENT_ACTIVATION_RECEIPT_ACK_REQUIRED` is retryable;
  host-owned authenticated receipt lookup can still reconcile a real
  post-commit/pre-ACK duplicate. Low-level `createActivationDispatcher()`
  retains a separately configurable strict flag, not the canonical default;
  host engineers using this advanced primitive should enable strict=true
  before production.
- For trigger create/update/pause/resume/delete, model-facing
  `control()` approval can provide **only**
  `{action:'execute',execution:{receiptId:HOST_ISSUED}}`.
  Removed old `execution.confirmationId` alias and stale
  `resolvedContext.confirmationId` fallback. The latter could reuse
  an approval across requests. Current live owner/actor identity,
  untrusted input refusal and host-owned mutation authorization remain
  mandatory. Trigger-control plane still expects the domain field
  `confirmationId` **internally** (canonical schema is unchanged).
- The old boolean `authorize()` hook and `AuthorizationDecision` type
  were removed earlier (#109). Unknown MCP Events compatibility profiles
  fail closed. Neither unsupported Pattern formats nor populated
  incompatible persisted states are auto-migrated.

These changes are intentionally breaking **before stable v1**. They
require an explicit published **new prerelease version**, controlled
consumer lockfile updates and complete host/real-DB revalidation; never
rewrite an already-published package in place.

## Evidence and limitations

- Source-backed all-export inventory and negative module import/host
  policy tests in `test/host-v1-api-contract-audit.test.mjs` and
  `test/host-receipt-acknowledgment.test.mjs`; real mock agent-mutation
  provenance regression in `test/embedded-host-kit.test.mjs`.
- Packed clean-room smoke, PostgreSQL schema/signature invalid-state
  refusal, explicit restore/rollback, registry profile and versioned
  compatibility map are **separate release gates**.
- These tests establish only **code-level compatibility cleanup**.
  They do not waive #317 independently deployed host security review,
  #47 measured operational PG/soak/failover, #48 authoritative external
  MCP frontier or #49 real provider billing, and do not authorize
  a stable v1 publication.

The architectural verdict is **no vendor-specific compatibility shims
or legacy approval paths in the supported canonical facade**.
Advanced low-level exports remain only where they expose separate
source/storage/discovery/dispatcher capabilities. Removing their
distinct use cases would be a separate public breaking API decision,
not a cleanup justified merely by overlap in function names.
