# Versioned compatibility, breaking changes and operator upgrade matrix

> **Release candidate described:** `mcp-event-intelligence@0.12.0-next.0`,
> current Git main at 2026-10-30. This document is a **pre-v1 candidate
> contract**, NOT an announcement that stable `1.0.0` is published,
> production-certified, or safe to upgrade without a host decision.
> Check the actual candidate tarball and Git HEAD before using these
> instructions for a later release. Tracks [issue #50](https://github.com/sarooo17/event-intelligence/issues/50).

The package version, MCP Events provider compatibility profile, trigger
wire language, signature identity and durable physical store version are
**different versioned surfaces**. A version number on one surface does not
establish compatibility on another. In particular the PostgreSQL schema
marker remaining `1` does NOT make old Pattern v2 signatures safe to reuse.

## Exact candidate support matrix

| Dimension | Current supported candidate value | Incompatible / not promised |
| --- | --- | --- |
| npm package / MCP Registry descriptor | `0.12.0-next.0` under npm `next` | Stable `1.0.0` **not released**; installing `latest` is not an opt-in to the prerelease |
| Node runtime | `>=22` (`package.json#engines`) | Node 20/18 and older not supported by candidate |
| Official MCP SDK | `@modelcontextprotocol/server@2.0.0` (dependency), optional stdio control plane | Other MCP SDK versions are **not** independently certified as EI's runtime dependency |
| MCP stdio protocol | optional stdio control plane targeting MCP `2026-07-28` (see `docs/PROTOCOL.md`) | Not a declaration that *every* older MCP SDK/protocol revision is supported |
| MCP Events provider ingress | `experimental-extension-2026-09-25`, capability `io.modelcontextprotocol/events`, `events/list`, `events/poll`; push/webhook normalize into same internal occurrence path | Unknown profile -> `MCP_EVENTS_PROFILE_UNKNOWN`; missing advertised extension -> no Events capability, **not** a legacy fallback; an opaque cursor does NOT prove event-time completeness |
| Canonical trigger wire | `protocolVersion: "0.2.0"`, `schemaVersion: "trigger.v0.2"` | Old pre-Pattern `expression`, `temporal`, `correlation`, `semanticCorrelation` trigger fields removed, no importer implied |
| Pattern AST wire | `version: "2"` | Pattern AST v1/legacy expression formats not supported as canonical v2 definitions |
| Pattern v2 persisted identity | independent signature marker `pattern_v2_candidate_signature`, **version 2** | Unmarked populated Pattern state and wrong marker version fail closed: `EVENT_INTELLIGENCE_PATTERN_V2_SIGNATURE_INCOMPATIBLE` |
| PostgreSQL physical schema | `POSTGRES_PERSISTED_SCHEMA_VERSION = 1`, validated physical catalog shape and metadata | Wrong marker -> `EVENT_INTELLIGENCE_POSTGRES_SCHEMA_INCOMPATIBLE`; wrong/missing physical tables/columns -> `EVENT_INTELLIGENCE_POSTGRES_SCHEMA_SHAPE_INVALID`; schema=1 is not cross-binary compatibility |
| Bundled JSONL | single-process reference store with separately persisted Pattern signature marker | Not suitable for concurrent independent processes; old populated unmarked state must not be auto-adopted |
| PostgreSQL driver | host-supplied `pg`-compatible pool, pinned candidate `pg@8.16.3` | No assertion of independent support for arbitrary drivers, DB proxies or PgBouncer transaction pooling |
| PostgreSQL CI evidence | actual PostgreSQL 16 required suite, shared-worker/restart/restore negatives | Not proof of production HA, off-host WORM, measured RPO/RTO or fully independent deployment |

## Enumerated breaking API changes and migration actions

| Before / obsolete contract | Candidate current behavior | Required host action |
| --- | --- | --- |
| `createEventIntelligenceAgentTools({ authorize })` with boolean `authorize()` and `AuthorizationDecision` | **REMOVED.** Host must provide durable-operation `tooling.control(request)`, returning `{action:'execute'}` or `{action:'return',result}`; authorize-only embedded integrations fail closed | Replace the old boolean authorization hook with a host-owned policy/approval/interrupt boundary; rerun lifecycle and unauthorized-owner tests |
| Host conformance report `event-intelligence.host-conformance.v2` / adapter lacking receipt replay | **v3** report requires `wakeId`, `runtimeReceiptId` and durable `readWakeReceipt(wakeId)` | Implement actual persistent host receipt lookup and post-restart source replay; don't return fabricated in-memory receipts |
| Pre-Pattern trigger fields / legacy expression language | Canonical Pattern AST v2 required, trigger `0.2.0` / `trigger.v0.2` | Recompile source trigger intent through the current planner, validate current schema, then **create new durable trigger IDs/versions** as needed; do not directly parse old JSON as new data |
| Old physical occurrence / candidate signature layout | Pattern v2 persisted signature identity now version 2 even though Pattern wire remains `2` and PostgreSQL store remains `1` | Stop all workers; full backup and explicit isolated reset/restore; never rename or silently mark old signatures compatible |
| Non-fenced multiworker host state in strict mode | `EVENT_INTELLIGENCE_REQUIRE_SHARED_STORE=true` rejects enabled connections lacking host authority epoch or PG `requireMcpSessionFence:true` | Owner provisions authoritative epoch and tests all active workers before enabling; no mixed fenced/unfenced writes in shared database |
| Deprecated/unlisted deep import paths | Only declared `package.json#exports` paths are the supported public npm import surface | Migrate to one of the current exports below; never import arbitrary `src/`, `dist/` or internal `scripts/lib/` paths except those explicitly exported |
| Legacy transparent consumption of old Muffin/Artemis integration versions | No runtime-specific compatibility adapter, no forced old-host support | Consumer owner modifies its own fork/lockfile and executes current host conformance; publishing EI does not update it |

The explicit public npm export map, verified by packed package checks:
`.`, `./host`, `./provider`, `./provider/erpnext`,
`./embedded`, `./observability`, `./conformance`,
`./storage/postgres`, `./storage/postgres/archive`,
`./storage/postgres/restore`,
`./storage/postgres/audit-archive`, `./diagnostics`.
Neither `scripts/validation/` provider-specific test adapters nor private
Muffin/Artemis glue should be treated as core ABI promises.

**Current embedded host migration** (replace host callbacks with real ones):

```js
import { createEmbeddedRuntimeIntegration, createEventSourceRegistry }
  from 'mcp-event-intelligence/embedded';

const ei = await createEmbeddedRuntimeIntegration({
  eventSources: createEventSourceRegistry({
    list: () => host.events.connections(),
    subscribe: refresh => host.events.onConnectionsChanged(refresh),
  }),
  activation: {
    resolveTarget: target => host.resolveContinuation(target),
    hasReceipt: receiptId => host.hasWakeReceipt(receiptId),
    deliver: ({activation,target,receiptId}) =>
      host.resumeFromEvent({activation,target,receiptId}),
  },
  tooling: {
    resolveContext: ctx => ({
      target: host.currentContinuation(ctx),
      owner: host.currentOwner(ctx),
      actor: host.currentActor(ctx),
    }),
    control: request => host.policy.control(request),
  },
});
```

The host owns credentials, MCP connection lifetime, tenant identity,
approvals, interrupt semantics and actual wake delivery. EI does not
authorize a host effect simply because a trigger matched.

## Durable-state upgrade / refusal / rollback

**Before deploying a new binary that can share a live database:**

1. Freeze new trigger writes, MCP ingests and wake effects; stop **all**
   old and new workers. A new marker alone does not fence an old writer.
2. Record each worker's exact package hash and current DB/JSONL marker,
   then take and **verify** a complete recoverable snapshot containing
   triggers, match history, source/cursor state, deadlines, deliveries,
   idempotency receipts, audit chain and metadata.
3. Start candidate only against a **separate restored clone** (PG16 or
   isolated JSONL). Run `npm run test:postgres`, current host conformance,
   scope isolation, receipt replay and source-cursor gaps there. Do not
   assume all legacy data can be mechanically transformed.
4. If startup rejects an incompatible shape, missing candidate signature
   marker on populated state, or an unknown profile, **leave the original
   store untouched**. A valid migration needs explicit code and audited
   mapping of candidate IDs, negative deadline IDs and wake receipts.
   Otherwise choose an operator-approved **fresh isolated store** and
   independently replay supported authoritative source history only
   after reconciling external host effects; if replay/receipt provenance is
   unavailable, abort the upgrade rather than deleting pending work.
5. Deploy only one compatible binary group to the shared store; enable
   `requireMcpSessionFence:true` and unique host authority epochs in
   strict multiworker environments; validate replays and owner isolation
   before unpausing effects.
6. For rollback, stop all current workers, restore the **entire previous
   snapshot** and its matching old binary. Do not manually rewrite the
   schema/signature markers or run old and new workers concurrently.

The `mcp-event-intelligence/storage/postgres/restore` archive helper is
**source-only isolated recovery**: it does not restore every trigger, wake,
receipt or audit event and cannot by itself justify a complete production
rollback. See `docs/POSTGRES-MCP-ISOLATED-ARCHIVE-RESTORE.md` and
`docs/EI-RELEASE-COMPATIBILITY.md`.

## Tested candidate vs. missing stable-v1 release signoff

- **Implemented and tested in current prerelease:** manifest parity,
  packed npm exports/type checks, canonical API/host conformance,
  PostgreSQL 16 startup schema and Pattern signature marker guards,
  operator-controlled logical restore test, strict shared-store opt-in.
- **Explicitly NOT certified:** actual external independently operated
  host/security signoff (issue #317), full PostgreSQL retention/HA/soak
  and complete SLO (issue #47), complete v1 compatibility audit (#50's
  other open acceptance), third-party provider event-time finality (#48),
  billed LLM budget/cancellation (#49), publisher/registry's actual
  stable `1.0.0` deployment.
- A published npm `next` prerelease is not an npm `latest` stable
  package, a verified production downgrade, or an authorization for
  old pinned Muffin/Artemis consumers to self-upgrade.
- After **stable v1.0**, the owner must publish an explicit SemVer/API
  stability policy. Do not retroactively infer it from pre-1.0 packages.

## Release checklist and primary sources

Before any manually authorized stable release, run the checked-out source
tests and examine the actual installed tarball, document the matching
source commit, update the full matrix above for any changed support
boundary, archive the database backup+rollback drill, attach an
independent-review signature, and complete the #317/#47 security/HA gates.
See [manual publishing](../RELEASE-MANUAL-PUBLISH.md), the
[pre-v1 policy](../EI-RELEASE-COMPATIBILITY.md), the
[protocol](../PROTOCOL.md), and [current release issue #50](https://github.com/sarooo17/event-intelligence/issues/50).
