# v0.6.0 — Pattern-only architecture

Event Intelligence v0.6 removes the pre-Pattern trigger architecture and makes Pattern AST the single canonical execution model.

## What changed

- persisted triggers are now `clauses + pattern + lifecycle/effect`;
- `TriggerPlanInput.pattern` is the only advanced authoring surface;
- simple plans compile deterministically to Pattern;
- temporal, correlation, aggregation, state and semantic reasoning all live inside Pattern nodes;
- `semanticCorrelation`, the legacy compiler and the legacy engine path are removed;
- the direct single-event `EventProcessor` path is removed;
- Activation Envelope v2 exposes the canonical Pattern and partition state;
- internal protocol/schema identifiers move to `0.2.0`, `ei.v0.2` and `trigger.v0.2`.

## Pattern wire version

The Pattern grammar still carries `version: "2"`. This is the version of the wire/schema grammar, not a second execution architecture.

## Compatibility

This is intentionally breaking. Pre-v0.6 persisted trigger definitions using `expression`, `temporal`, `correlation` or `semanticCorrelation` are not accepted by the v0.6 runtime.

Historical v0.5 and earlier release notes remain available for reference.

## Production posture

The embedded/host-owned MCP architecture remains unchanged. JSONL remains a single-process reference backend; production HA/Postgres work is tracked separately. Shared-store mode continues to fail closed unless a backend advertises the required strong/distributed capabilities.

## Verification

Release acceptance requires CI, Clean-room Smoke, Security Scan, MCP Launch Check and Public Release Check to be green on the release commit.
