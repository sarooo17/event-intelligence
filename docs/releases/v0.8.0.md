# MCP Event Intelligence v0.8.0

v0.8.0 adds a runtime-neutral embedded integration surface for agent and workflow runtimes.

## Embedded runtime integration

- add `createEmbeddedRuntimeIntegration()` above the lower-level host kit;
- add `createEventSourceRegistry()` for host-owned event/MCP connection discovery;
- add EI-neutral capability metadata and a portable tool catalog;
- keep tool exposure and SDK translation host-owned instead of shipping a per-runtime adapter matrix;
- add host-owned result projection with optional runtime result references;
- keep tooling optional for runtimes that do not expose Event Intelligence operations directly to a model.

## Host control and interrupts

Durable EI mutations now support a host control contract:

- `{ action: "execute", ... }` proceeds with the mutation;
- `{ action: "return", result }` returns an opaque host-owned outcome.

The host can use that outcome for deny, approval, interrupt, defer, budget, quota or tenant-policy semantics. Event Intelligence does not interpret those meanings. Native host interrupt/suspension exceptions also pass through unchanged.

## Runtime independence

Event Intelligence core contains no named-runtime dispatch and intentionally ships no `toOpenAI()`, `toAnthropic()`, `toMuffin()`, `toArtemis()` adapter matrix. New runtimes consume the same neutral contracts and translate them at their own boundary.

Continuation targets remain opaque `{ runtime, kind, id }` references. MCP transports, credentials, runtime policy, result storage and continuation semantics remain host-owned.

## Verification

The integration contract is covered by generic third-party-shaped and headless runtime tests, host-owned interrupt/result tests, capability filtering, source-registry composition, packed-package smoke checks, security scans and MCP registry checks.
