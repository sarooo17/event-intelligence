# MCP Event Intelligence v0.2.0

Production-hardening release focused on making Event Intelligence safe to embed once in a shared agent host.

## Highlights

- native tenant/workspace isolation through scoped store partitions and `host.scope(scopeId)`;
- injectable storage backends while keeping `PersistentEventStore` as the zero-dependency default;
- durable wake delivery with claims, leases, bounded retry, dead-letter handling and restart recovery;
- reconciliation after the runtime receipt is persisted, without redelivering after a crash;
- single-flight MCP polling plus bounded multi-page draining;
- composite engine split into explicit storage, matching, graph and lifecycle/deadline/audit modules;
- provider-native ERPNext Events adapter exported as `mcp-event-intelligence/provider/erpnext`.

## Delivery semantics

v0.2.0 strengthens effectively-once activation without claiming distributed exactly-once delivery. Stable wake IDs, persisted delivery state, runtime receipts and lease-based claiming prevent duplicate ownership in the validated scenarios. Receivers should still honor the stable wake ID as an idempotency key.

## Storage and HA

The bundled JSONL store is intentionally a single-process reference backend. Shared/horizontally scaled deployments can inject another store; distributed implementations must preserve scope isolation and implement wake claim/lease operations atomically.

## Compatibility

The persisted Event Intelligence trigger protocol/schema remains compatible with the v0.1 line. MCP Events remains experimental and is not represented as finalized MCP conformance.
