# v0.6.1 — Post-merge correctness fixes

v0.6.1 is a patch release for three P2 findings from the automated review of the v0.6 architecture merge.

## Fixed

- **Store conformance trigger fixture:** the advertised `runStoreConformance()` harness now uses the v0.2 Pattern trigger schema instead of the removed v0.1 `expression + temporal` representation.
- **Wake conformance contract:** the harness now creates a valid Pattern match and passes its `matchId` into `ensureWakeDelivery()`, matching the v0.6 durable wake contract.
- **Temporal completion timestamps:** when several Pattern candidates become due before one scheduler tick, each emitted match derives `completedAt` only from the deadline identified by its own candidate signature/condition ID. One candidate can no longer inherit another candidate's later deadline.

## Regression coverage

A new temporal regression test creates two independent candidates with deadlines one minute apart, lets both become due before the scheduler runs, and verifies that their completed timestamps remain distinct and equal to their own deadlines.

## Compatibility

No new wire-format break is introduced. Internal protocol/schema versions remain `0.2.0`, `ei.v0.2` and `trigger.v0.2`.

## Release pipeline

The release workflow also retains the npm propagation hardening added after v0.6.0 so successful trusted publishes are not mistaken for release failures while the registry is still processing the new version.
