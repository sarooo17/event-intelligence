## SDK scope

- Runtime-neutral embedded/host-owned integration; MCP Events source and downstream final authorization remain host responsibilities. Node >=22; ESM.
- Canonical Pattern AST v2, source-aware matching, durable triggers/receipts, explicit host-issued receipts, cancellation/revocation fencing, multi-tenant PostgreSQL16 store and restart/replay conformance.
- Strict, bounded causal explainability with explicit unknown/partial fidelity when upstream event-time completeness is unavailable, plus tested separate first-party MCP source oracle.
- **Opt-in** semantic evaluation through host-provided evaluator: deterministic prefilters, tenant/context versioned cache and durable PostgreSQL per-trigger/per-batch call/token/**host-reserved estimated cost** limits. No promise about actual remote billing or cancellation.
- Conservative **lossless no-prune** event/match/audit/receipt policy. Safe terminal duplicate-history compaction only. Operators must size and back up stores for indefinite growth; no WORM or production HA certificate.
- Reviewed [PR #407](https://github.com/sarooo17/event-intelligence/pull/407) removed a quadratic per-write audit-history replay under scope advisory lock while preserving the canonical hash chain. Separate first-party Railway 1k/1k at 5/s had zero bounded-ingress refusals and 1,000 host receipts; higher-scale / independently operated production SLO certification remains unresolved in [#376](https://github.com/sarooo17/event-intelligence/issues/376).

## Breaking/API, wire and stored-state compatibility

The authoritative [versioned compatibility matrix](1.0.0-compatibility.md) lists **all** supported public exports, Node/MCP/Pattern/trigger/provider versions, old `authorize()` removal, required `control(request)`, mandatory host-issued `runtimeReceiptId`, host conformance v3 and deprecated confirmation alias removal. No implied import compatibility with unlisted deep paths or older trigger expression formats.

The PostgreSQL physical schema marker and Pattern-v2 signature marker have **independent identities**. Before changing a live host: stop every worker attached to the same store, take an operator-verified full backup, check schema and signature markers, validate replay/receipts in an isolated clone, then explicitly approve a compatible upgrade or fail closed and restore/reset under operator control. No silent migration, mixed fenced/unfenced writer rollout or automatic downgrade. This npm package does not touch downstream Muffin/Artemis pins.
